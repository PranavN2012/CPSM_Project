NLP Intelligence Engine

5 NLP techniques that convert raw security alerts into clear, human-readable reports — entirely offline, no external AI required.

Template-Based NLG

Structured sentence generation using data-driven slot filling

Uses pre-written sentence templates that get filled in with real data — like a smart form letter for security alerts.
Every report follows a clear 3-part structure: What happened → Why it's dangerous → What we did about it.
Automatically links each finding to the relevant compliance rules: SOC 2, PCI-DSS, and CIS.
"A change in account 987654321098 made S3 bucket prod-data-lake publicly accessible in us-east-1. This risks unauthorized data exposure, violating CIS AWS 2.1.5, SOC 2 CC6.1, PCI-DSS 7.1. CloudSentry immediately blocked public access automatically."

Sentiment-Weighted Scoring

Assigns risk severity by analyzing keywords found in resource names

Scans the resource name (e.g., an S3 bucket called "prod-customer-data") and uses the words inside it to estimate how sensitive the asset is.
30+ keywords are scored across three risk levels — Critical ("prod", "payment"), High ("backup", "audit"), and Low ("dev", "test").
A higher cumulative score produces more urgent language in the generated report, ensuring critical assets get immediate attention.
"The resource name contains 'prod', 'data' — words that signal a live, sensitive system. CloudSentry upgraded this alert to CRITICAL priority and flagged it for immediate review."

Named Entity Recognition (NER)

Extracts AWS service names and permissions from raw IAM policy text

Parses raw IAM policy JSON and identifies every AWS service mentioned — similar to scanning a legal document and highlighting every key party involved.
Converts shorthand prefixes like s3: and ec2: into full human-readable names (e.g., "Simple Storage Service") — covering 14 core AWS services.
Flags dangerous wildcard (*) permissions — policies that grant unrestricted access to every resource and action across the entire AWS account.
"Detected a wildcard policy (Action:*) — this user has full control over your entire AWS account, including S3, EC2, Lambda, IAM, and more. Immediate review required."

Temporal Context

Detects recurring issues by analyzing the history of past security events

Queries the security event database and counts how many times the same misconfiguration has occurred before in the same account.
Distinguishes between a one-time mistake and a recurring pattern — giving your team the context needed to decide the right level of response.
Repeated violations in the same account often indicate a systemic root cause — such as a misconfigured CI/CD pipeline or a team knowledge gap.
"TEMPORAL ANALYSIS: This is the 5th time an S3 Public Access issue was found in account 123456789012. This is no longer a one-off — it looks like a recurring process problem."

Cross-Event Correlation

Links related security events to detect multi-step attack patterns

Searches the event database for other misconfigurations in the same account — connecting separate alerts that may be part of one coordinated attack.
Identifies multi-step attack sequences by matching event combinations against known MITRE ATT&CK kill-chain patterns.
Detects high-risk attack workflows including Lateral Movement (spreading access), Data Exfiltration (stealing data), and Total Compromise (full account takeover).
"CORRELATION ALERT: An IAM privilege escalation occurred in this account just before a network security group was opened. Together, these events match a lateral movement kill chain — suggesting an attacker escalated permissions first, then opened SSH access to move deeper into the infrastructure."
